on-demand variant User parameter overrides → Lambda / Modal render → signed URL.

From the recap page, a variant form lets a creator override sponsor tier visibility, music track, locale (en / zh / id), or scene order. Worker posts to POST /api/recap-reel/render with the override payload, returns a render-job id, polls until ready, opens the signed R2 URL. Typical latency 30–90s on Lambda / Modal.

How this slots into the existing event-recap stack

  1. Mocks A + B live in workers/aie2026-vibes.ts (and the generic event-recap-vibes.ts template) — adding a renderHeroReel() + renderSponsorBand() next to the existing renderShell(). Data already exists in EventRecapBundle: top reach posts (for reel tiles), storyId: 'sponsors-booths-hiring' + sponsor allowlist (for tier band), voices (for the carousel).
  2. Mock C introduces a Remotion composition at src/remotion/EventRecap/{index.tsx,Title.tsx,StatScene.tsx,RankingScene.tsx,MomentScene.tsx,MontageScene.tsx,CascadeScene.tsx,SponsorScene.tsx,Outro.tsx}. renderRecapReel(bundle, config, variant) uses @remotion/renderer on Lambda/Modal, writes recap-9x16.mp4 + recap-16x9.mp4 to R2 at event-recap-{eventId}/. Cron hook in slice 11 calls it post-refresh.
  3. Mock D is a new Next.js route at app/vibes/aie/page.tsx. Reads each AIE EventConfig, fetches public bundles in parallel, renders the grid + cross-event consolidation. Cross-event computation lives in lib/research/event-recap/aggregate.ts — pure function over `EventRecapBundle[]`.
  4. Reusability: the recap reel + sponsor band + voice carousel are React components that take EventRecapBundle + EventConfig. The generic event-recap-vibes.ts worker template already supports per-event config — adding a new event (e.g. AIE Tokyo 2026) is a config commit + worker route, no UI fork.
  5. Provenance (CLAUDE.md hard rule #8): each rendered MP4 records a versioned ToolRef with { inputs: bundle.id, outputs: r2Path, beforeSnapshotRef, afterSnapshotRef, variant } so reruns are auditable.
